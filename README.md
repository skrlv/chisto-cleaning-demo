# Чисто — демонстрационный сайт клининговой компании

Готовый русскоязычный пример для портфолио: лендинг, интерактивный расчёт, форма заявки и демонстрация кабинета. Компания вымышленная, тарифы условные. По умолчанию ни одна заявка не отправляется во внешние сервисы.

## Публичное портфолио на GitHub Pages

Для этого и следующих демонстрационных проектов выбран **GitHub Pages**: бесплатная публикация статических сайтов из публичных репозиториев, без собственного сервера. [Описание GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Основа публикации — [официальный workflow Next.js от GitHub](https://github.com/actions/starter-workflows/blob/main/pages/nextjs.yml).

Репозиторий: [skrlv/chisto-cleaning-demo](https://github.com/skrlv/chisto-cleaning-demo). Адрес после успешного workflow: [skrlv.github.io/chisto-cleaning-demo/](https://skrlv.github.io/chisto-cleaning-demo/), кабинет — [cabinet/](https://skrlv.github.io/chisto-cleaning-demo/cabinet/).

Файл `.github/workflows/pages.yml` проверяет расчёт и серверную логику имитациями, собирает статическое демо, проверяет ссылки и публикует `out/` после каждого push в `main`. В Settings → Pages должен быть выбран источник **GitHub Actions**. Собственные ключи для этого workflow не нужны: используются стандартные краткоживущие разрешения GitHub Actions.

Публичная версия всегда работает в режиме `demo`. Калькулятор, форма, локальное сохранение и статусы работают; серверный Telegram API в статическую публикацию не входит. Заявки относятся к браузеру посетителя и не являются общим кабинетом компании. Для настоящей обработки клиентов нужна отдельная серверная версия.

Проверка статической версии локально:

```sh
npm run build:pages
npm run check:pages
npm run preview:pages
```

Откройте [статическое демо](http://127.0.0.1:4173/chisto-cleaning-demo/). Папка `out/` содержит готовый сайт. Сборка выполняется в `work/pages-build/`, чтобы сохранить обычную серверную `.next` и работающий локальный просмотр. Файлы `.env` не копируются; Telegram-переменные очищаются, а режим принудительно устанавливается в `demo`.

Путь проекта определяется по `GITHUB_REPOSITORY` во время Actions. Для пользовательского репозитория `owner.github.io` используется корень, для других — `/имя-репозитория`. Локально по умолчанию применяется `/chisto-cleaning-demo`; другой путь можно передать в `NEXT_PUBLIC_BASE_PATH`. Для собственного домена нужен пустой путь. После изменения пути пересоберите сайт и задайте тот же путь при локальном просмотре.

Это демонстрация для портфолио. [GitHub Pages не предназначен для хостинга действующего интернет-магазина или коммерческого SaaS](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

## Запуск

Нужны Node.js **22.18 или новее** и npm. Для разработки рекомендуем актуальную LTS-версию Node.js. Во время первого `npm ci` нужен интернет; затем сайт работает локально без базы данных, ключей и платных сервисов. Фотография, иконки и стили доступны из самого проекта, внешних шрифтов нет.

```sh
npm ci
npm run dev
```

Откройте [сайт](http://127.0.0.1:3000) и [демонстрацию кабинета](http://127.0.0.1:3000/cabinet). Используйте один и тот же адрес: `localhost` и `127.0.0.1` имеют разные локальные хранилища.

Для производственной сборки (сначала остановите dev-сервер на том же порту):

```sh
npm run build
npm start
```

`Ctrl+C` останавливает сервер. По умолчанию он слушает только `127.0.0.1`, поэтому этот адрес доступен на текущем компьютере. Для публичного показа используйте GitHub Pages, описанный выше.

### Фоновый запуск на macOS

Чтобы локальная ссылка продолжала работать после закрытия окна команд, запустите файл **«Запустить сайт.command»** двойным щелчком в Finder или выполните:

```sh
npm run preview:start
```

Команда запускает производственную сборку через временную пользовательскую задачу macOS. Сервер работает независимо от сессии Codex и только на этом компьютере. Автозапуск после входа в систему не устанавливается; после перезагрузки компьютера запустите его снова. Если готовой сборки нет, она будет создана автоматически. После изменения исходников пересоберите сайт перед фоновым запуском.

Этот способ всегда включает демонстрационный режим и отключает Telegram-ключи. Он предназначен для показа портфолио. Для остановки:

```sh
npm run preview:stop
```

Журнал запуска находится в `.preview/server.log`. Он не включается в архив исходников. Ошибка `ERR_CONNECTION_REFUSED` означает, что на указанном локальном адресе не запущен сервер. Одновременный запуск `npm run dev` или `npm start` на порту 3000 требует сначала остановить фоновый сервер.

## Показ предпринимателю

1. Выберите вид уборки, площадь и дополнения. Расчёт меняется сразу.
2. Заполните форму **вымышленными** именем и телефоном, например `Демо Клиент` и `+7 (999) 000-00-00`.
3. После «Демо-заявка сохранена» откройте кабинет.
4. Измените статус, обновите страницу и отфильтруйте заявки.
5. При необходимости очистите демо-данные: действие требует второго нажатия с подтверждением.

Дата означает пожелание клиента и не бронирует время. Демо-кабинет не требует входа и не подходит для настоящих персональных данных.

## Режимы и переменные окружения

Без `.env.local` работает `demo`. Чтобы настроить режим, скопируйте пример:

```sh
cp .env.example .env.local
```

| Переменная           | Назначение                                                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `APP_MODE=demo`      | Локальное демо: заявка сохраняется в localStorage. Значение по умолчанию.                                                  |
| `APP_MODE=telegram`  | Отправка через серверный POST `/api/leads`, без локального демо-сохранения.                                                |
| `TELEGRAM_BOT_TOKEN` | Токен бота, только на сервере.                                                                                             |
| `TELEGRAM_CHAT_ID`   | Идентификатор чата-получателя, только на сервере.                                                                          |
| `TRUST_PROXY=0`      | Общий лимит для одного процесса, без доверия входящему `X-Forwarded-For`.                                                  |
| `TRUST_PROXY=1`      | Отдельные лимиты по первому IP из `X-Forwarded-For`; допустимо лишь за доверенным прокси, который заменяет этот заголовок. |

Перезапустите сервер после изменения переменных. Секреты не имеют префикса `NEXT_PUBLIC_`, не попадают в клиентский код и не должны попадать в Git. Существующую `.env.local` не добавляйте в архив проекта.

### Демо

Ключ хранилища: `chisto.demo.orders.v1`, формат `{ version: 1, orders: [...] }`, максимум 200 заявок. Сохраняются параметры, контакты, идентификатор, время, статус и сумма. Статусы: «Новая», «Связались», «Согласована», «Завершена».

Чтение хранилища выполняется после гидратации. Повреждённые данные не перезаписываются незаметно: интерфейс объясняет ошибку и позволяет явно очистить демо-данные в кабинете. Ошибки доступа и переполнение не дают ложного подтверждения сохранения. Очистка удаляет только ключ этого приложения. Другие вкладки получают обновления через событие `storage`.

Данные относятся к текущему origin и профилю браузера. Они исчезнут при очистке данных сайта; приватный режим также может их не сохранять. Одновременная запись из нескольких вкладок не является транзакцией. Это демонстрационное хранилище, не CRM.

### Реальная отправка

Для включения установите `APP_MODE=telegram`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Сервер проверяет поля и диапазоны и заново рассчитывает сумму по своим тарифам. Переданный браузером итог игнорируется. Используется [Telegram Bot API, sendMessage](https://core.telegram.org/bots/api#sendmessage), текст без HTML-разметки.

Сервер принимает JSON до 16 КиБ только с Origin этого сайта. Тайм-аут Telegram — 8 секунд. Успех возвращается лишь после HTTP-успеха и ответа Telegram `ok: true` с `message_id`. При отсутствующей конфигурации, ошибке API, сети или тайм-ауте показывается ошибка. Перехода в демо-режим при сбое нет.

Клиент блокирует повторное нажатие и передаёт UUID в `Idempotency-Key`. Сервер хранит отпечаток проверенного содержимого. Уже подтверждённая заявка с тем же ключом повторно не отправляется; изменённое содержимое и параллельные запросы отклоняются. После неясного результата повтор с тем же ключом блокируется: сообщение могло успеть дойти. Оператор должен проверить Telegram до создания новой попытки.

Ограничение частоты — **5 попыток за минуту**. По умолчанию лимит общий для процесса, чтобы не доверять подделываемым proxy-заголовкам. Ограничители и ключи повторов находятся в памяти, максимум по 1 000 записей; срок ключа — 24 часа. Перезапуск сбрасывает защиту, разные экземпляры сервера её не разделяют. Это подходящая защита локального однопроцессного примера, но она не обеспечивает гарантии доставки и exactly-once в публичном сервисе.

Перед работой с настоящими клиентами подключите серверный хостинг с HTTPS, постоянное общее хранилище заявок и ключей повторов, распределённое ограничение частоты/защиту от спама, авторизацию рабочего кабинета и мониторинг ошибок. Настройте обработку персональных данных и реальные условия сервиса. Демо-кабинет нужно заменить защищённым рабочим интерфейсом. Также согласуйте настоящие тарифы, перечень работ и контакты компании.

При разработке реальные аккаунты не подключались, внешние сообщения не отправлялись. Telegram проверяется имитациями сервиса.

## Выполненная проверка

13 ноября 2026 года прошли 27 модульных и серверных тестов, 10 браузерных сценариев на производственной сборке в Chromium, проверка TypeScript и производственная сборка. Проверены ширины 1440, 375 и 390 px, горизонтальная прокрутка, клавиатурный фокус, создание заявки, статусы после обновления, фильтр и очистка. Проверены повреждённое и недоступное хранилище, отсутствие настроек Telegram, имитации сбоя API и сети, защита от двойной отправки и отсутствие ложного успеха. Во время основного демо-сценария не было запросов к `/api/leads` или Telegram. Safari и Firefox отдельно не проверялись.

## Проверки

```sh
npm test
npm run typecheck
npm run build
```

Модульные тесты используют встроенный тестовый модуль Node.js и не требуют дополнительных библиотек. Они покрывают 4 000 ₽ / 8 800 ₽ / 3 700 ₽ из задания, минимум, границы, неверные параметры, повреждённое/недоступное хранилище, сохранение и статусы. Серверные тесты имитируют успешные и ошибочные ответы Telegram, тайм-аут, дубли, лимиты, неверные поля и подмену цены.

Браузерные сценарии запускаются через Playwright. Один раз загрузите Chromium:

```sh
npx playwright install chromium
npm run build
npm run test:e2e
```

Тесты автоматически запускают два изолированных локальных сервера на портах 3002 и 3003. Оба принудительно работают без Telegram-ключей; второй включает реальный режим только для проверки ошибки отсутствующей конфигурации. Эти порты должны быть свободны. Проверяются 1440 px и 375/390 px, отсутствие горизонтальной прокрутки, синхронизация полей, клавиатура и фокус, валидация, полный путь заявки, сохранение статуса после обновления, фильтр, очистка и отсутствие ложного успеха. Тесты не используют и не очищают данные вашего обычного браузера. Артефакты проверок сохраняются в `work/browser-results` рядом с каталогом проекта.
